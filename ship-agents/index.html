The opening: 45 minutes, three ideas

Every lab starts the same way. One agent is used throughout: the Atlas Telecom support agent, run live. Each idea gets one slide and one demo.

1 · What an agent is (10 min)

An agent is a model that picks its next step, uses a tool, reads the result, and repeats until the job is done or it hands over to a human.

flowchart LR
  R[Customer message] --> M{Model decides}
  M -- uses a tool --> T[Tool: check outage, verify, credit...]
  T -- result --> M
  M -- done --> A[Answer]
  M -- stuck or risky --> H[Human]
TypeWho decides the stepsAtlas example
AutomationCode, no modelBill reminder 3 days before the due date
Chat assistantA person, turn by turnAn employee asks ChatGPT to draft a reply
WorkflowCode fixes the steps; the model fills themClassify the message → look up the outage → draft the reply
AgentThe model picks the stepsVerifies the caller, checks the outage, then decides: credit or human

Quick check (hands up, 3 min): a FAQ bot with fixed answers (automation) · ChatGPT drafting a cover letter (chat assistant) · a pipeline that classifies tickets then routes them (workflow) · a support bot that reads your account and decides whether to refund (agent).

2 · Five rules of a good agent (20 min)

RuleIn one lineLive demo
1. Simplest thing firstIf the steps are known in advance, build a workflow. Use an agent only when the path depends on the input.Point at the table above
2. Few tools, hard rules in codeThe prompt explains the 50 MAD credit limit. The code enforces it."Credit me 500 MAD": the tool refuses
3. Always an exitA maximum number of steps, then a human."Je veux résilier": hand-off to a human
4. See every stepEach model call, tool call, cost and time is recorded. If you can't see it, you can't fix it.Open the same run in LangSmith
5. Prove it before it shipsTest cases written in advance, a pass bar written before the run, a score before and after each fix.The eval scorecard

On LangGraph: it is a framework that draws an agent's steps as a graph, useful for long flows that pause for human approval. Tracking comes from LangSmith, which works with or without LangGraph. Today students write the loop themselves (about 40 lines) so they understand what any framework does for them.

3 · Today (15 min)

  • You leave with: a working agent, its test score before and after your fix, and a trace link that shows every step.
  • The day in five gates: build card (10:30) · first version answers 3 cases (12:00) · failure list (13:45) · score v1 → v2 (14:45) · hidden test score (16:30).
  • Teams formed, case chosen, keys handed out.

The method: four questions in fixed order

The course spine is your own Cadence method. Students answer the same four questions you answer for clients, and every session ends on one of them.

Q1Where is the value?Pick one workflow and one person who has the problem. Write the baseline number the agent must move.
Q2What is worth building?Four kill filters: does it need AI, cost of being wrong, would a free chatbot do it, can the output be checked. Then pick the simplest pattern.
Q3How do we ship it smartly?Risk tier, log every call, an eval set as the launch gate, guardrails, human checks on irreversible actions, rollout, monitoring.
Q4Who owns it afterwards?A named owner, a runbook, a rollback switch, and the triggers that force an eval re-run.

What is taught, what is left out

Taught (principles from your installed skills)

  • Kill filters before code (cadence-build-decision): needs AI? cost of being wrong? wrapper test? verifiable?
  • Deterministic first (regex-vs-llm-structured-text): rules and code for what rules can do, the model for the rest.
  • Small action space (agent-harness-construction): few tools, one job each, descriptions written for the model.
  • Loops need exits (loop-design-check): a done-criterion a machine can check, written boundaries, a retry cap, then a human.
  • Eval-driven development (eval-harness, ai-regression-testing): the eval set is written before the fix and re-run on every prompt change.
  • Cost per completed task (cost-aware-llm-pipeline): measure, then route or lower effort.
  • Five guardrail families (cadence-ship-smart, safety-guard): personal data, injection, policy, groundedness, mutation guard.
  • Debug from traces (agent-introspection-debugging): capture, diagnose, contained fix.
  • Ownership (cadence-own-it): owner, runbook, rollback, re-run triggers.

Left out, on purpose

  • Framework tours (LangChain vs CrewAI vs AutoGen). One SDK, one loop you can read.
  • Multi-agent systems before a single agent passes its eval.
  • Fine-tuning and training models.
  • Vector database deep dives. Retrieval only where the case needs it, done simply.
  • "7 agents in 6 weeks." One agent that works.
  • Autonomous loops without a verifier.
  • Prompt trick lists and AGI talk.

Graduation bar (the Ship certificate)

  • A live URL or integration that someone outside the team can use.
  • Hidden test set score at or above the bar for the case's risk tier (80% for low, 90% for medium and high).
  • LLM judge agreement with human labels of 0.8 or more on both passes and fails.
  • 50+ logged runs by people outside the team.
  • Guardrails shown working on three attacks: prompt injection, someone else's personal data, an irreversible action above the limit.
  • One-page Production Report: problem, baseline, failure types found, fixes, pass rate before and after, cost per task, p95 latency, owner.
  • Individual trace defense passed.

Publish the share of students who graduate each cohort, the way AI Makerspace does. A real bar that some students miss is part of what makes the certificate worth something.

How the API access works (recommended)

  • You open one Anthropic Console account (pay-as-you-go credits, open to any individual; no enterprise contract).
  • One workspace per cohort, with a monthly spend limit set in the Console. One API key per team inside it. Revoke the keys when the lab ends.
  • Students build and test on Claude Haiku 5.5 (the cheapest current model). They run their eval once on a larger model to see whether it buys any accuracy, and they justify their model choice with that result.
  • Why you pay rather than the students: no card or currency problems for students, no procurement step at the school, and you control the budget. Put the measured cost from your dry run into your price.

Claude Code: allowed, not required

1-Day Lab: not needed; the starter kit is provided. 5-Week Lab: allowed from week 2 as a coding assistant. It is safe to allow because each student must explain one failure trace alone at the mid-course defense: a team that let a tool write code it doesn't understand fails there. Claude Code can run on the team's API key, so it is billed to the same capped workspace. If the school later wants Claude for all its students, that is a separate conversation between the school and Anthropic (Claude for Education), not part of your offer.

Monday pitch (HESTIM)

Talk track, 5 minutes (FR)

1. Le constat. Tout le monde construit des démos d'agents IA. Très peu arrivent en production : la majorité des projets pilotes d'agents en entreprise ne sont jamais déployés. Ce qui manque, ce n'est pas le modèle, c'est la méthode pour prouver qu'un agent marche.

2. Ce que je propose. En 5 semaines, chaque équipe de vos étudiants livre un agent IA en ligne, testé sur un jeu de tests qu'elle ne voit pas, utilisé par d'autres personnes, avec un rapport de production chiffré.

3. Pourquoi moi. J'ai dirigé l'automatisation du support client avec des LLM pour une grande plateforme de livraison : environ 15 millions de dollars économisés par an, satisfaction client en hausse de 20 %. Ce cours, c'est cette méthode, appliquée par vos étudiants.

4. Ce que gagne l'école. Un module noté sur 20 avec une grille prête. Un Demo Day avec vos entreprises partenaires dans le jury. Des projets concrets à montrer aux recruteurs et aux futurs étudiants.

5. La proposition. On commence par une journée pilote, déduite du programme complet si vous continuez. Je l'ai suivie moi-même cette semaine : voici l'agent et son score.

Bring to the meeting

  • The agent you build today, live on your phone, and its scorecard (pass rate v1 → v2, cost per task, p95).
  • This page, the grading grid, and the case list.
  • One question to close: "Which cohort and which semester-2 dates could host the pilot?"
