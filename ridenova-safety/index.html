Problem structure (MECE)

Four levers that cover the case lifecycle, ordered by risk removed.

Each lever maps to one stage: detect, inform, route, reduce. The order is deliberate: the lever that saves the most hours (auto-resolution) also carries the most risk, so it ships last and behind a gate.

Resolve every report at the right speed, with the right human, at lower cost
1Never miss dangerSOS, stalking telematics, medical and weapon language → L4 + alert, lockedP0 · built
2Find information faster6 systems on one screen, fact-level provenance, masking, translationP0 · built
3Route by severityAI proposal → guardrails → tier, action, deadline-ordered lanesP1 · built
4Remove safe low-risk workL1 auto-resolve on an allow-list, confidence gate, 5% QAP2 · gated
Design principles

The AI proposes, rules constrain, and a human decides.

Automate upstream, decide in the console

  • Triage, paging and L1 closure run at intake, before any queue
  • The console holds only human work: respond (L4), decide (L2–L3)
  • Auto-resolved cases appear only as a QA and audit view

Fail toward a human

  • Unrecognised → L2 human, never L1
  • Auto-resolve is an allow-list, not the default
  • Invalid AI output → safest values
  • AI outage → rules keep the queue moving

Guardrails are code, not prompts

  • SP-7 → L4, alert, locked
  • SP-8 and threats → L3 floor
  • Injection → specialist review (L3), confidence capped
  • SP-9, duplicates, missing data

PII never leaves the boundary

  • Structured and free-text redaction before the AI sees anything
  • Pseudonymous IDs; the server refuses PII-looking payloads
  • Role masking; every reveal logged with a reason
  • No PII in logs or exports; retention purge

ANTHROPIC_API_KEY=… npm start   # live mode
